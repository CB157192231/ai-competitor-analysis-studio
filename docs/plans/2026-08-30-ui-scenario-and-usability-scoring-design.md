# UI 场景价值与上手成本评分设计

## 目标

现有界面分析能说明产品页面怎样组织，但还没有回答两个更直接的问题：这个产品最适合替用户完成什么工作，以及普通用户要付出多少学习和操作成本才能拿到结果。

新增分析必须使用白话，并且能从真实应用界面、官方使用指南或可信实操视频回到证据。没有执行页、失败页或结果页时，明确标为“证据不足”，不能用官网功能描述代替。

## 场景价值地图

每个产品输出 3–4 个工作场景。每个场景包括：场景名称、适合度 1–5 分、适用工作、价值原因、证据界面和限制。5 分表示该产品能把这类工作从发起推进到可验收结果，并且发挥了自己的独有优势；3 分表示可以完成但没有明显优势，或仍需要用户频繁介入；1 分表示不适合或缺少关键环节。

最终必须给出一句“最能体现价值的场景”，例如“WorkBuddy 最适合需要读取本地文件、分步骤执行并交付文档的办公任务”，不能只写“办公自动化”。

## 上手成本评分

总分使用 5 分制，分数越高表示越容易上手、使用成本越低。六个分项权重相同：

1. 入口清晰：用户是否一眼知道从哪里开始。
2. 首次配置：开始前需要理解和设置多少概念。
3. 操作步骤：从发起到运行需要多少跳转和选择。
4. 运行反馈：用户是否知道任务正在做什么、是否卡住。
5. 失败恢复：用户能否停止、重试、续跑或看到失败原因。
6. 结果验收：结果是否容易预览、修改、下载或复用。

每项必须包含评分、白话原因和证据界面。总分之外再给出证据置信度：高表示六个阶段基本齐全，中表示缺一到两个关键阶段，低表示主要只有首页或配置页。缺证据不等于体验差，但结论必须标为暂定。

## 输出位置

- 网页：在产品与交互逻辑后增加“场景价值地图”和“上手成本对比”。
- PPTX：增加一页场景价值和一页上手成本，放在真实界面证据之后。
- DOCX：增加逐品场景价值表与六项评分表。
- JSON：保存在每个 `competitorAudit` 的 `scenarioValue` 与 `usabilityScore` 字段，保证历史项目再次载入后仍可修改和导出。

## 验收

- 三个产品的最佳场景和总分不能完全相同。
- 每个分项必须有白话原因，不能出现“交互侧重点”“信息架构较好”等空结论。
- 缺少执行、恢复或结果证据时必须显示置信度和证据缺口。
- PPTX 与 DOCX 使用和网页相同的数据，不再另写一套结论。
