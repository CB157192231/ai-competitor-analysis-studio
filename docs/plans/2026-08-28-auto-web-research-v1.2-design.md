# 自动联网竞品分析 v1.2 设计

## 目标

用户只输入目标产品名即可得到有公开来源支撑的竞品分析。系统默认自动发现直接竞品和间接竞品，调用 DeepSeek Responses API 的服务端 `web_search`，把检索到的官网、定价、文档、帮助中心和可信行业资料整理成证据台账，再生成可追溯的结构化分析。

## 方案选择

采用 DeepSeek 原生 `web_search`，不新增搜索服务或 API Key。与本地抓取搜索引擎相比，该方案部署更简单、失败面更小，也能沿用现有 DeepSeek 密钥。保留原 Chat Completions 路径作为关闭联网调研时的兼容模式。

## 数据流

1. 用户输入目标产品，可选填写已知竞品与内部证据。
2. 网页默认提交 `autoResearch=true`、`autoDiscover=true`。
3. 本地服务调用 `/responses`，强制启用 `web_search`；只有 `deepseek-v4-flash` 参与联网分析。
4. 模型先搜索并核对一手资料，再输出 Schema 1.2 JSON。
5. 服务端归一化结果、校验证据 ID、压低无证据高分，并补充搜索调用次数和调研状态。
6. 网页展示调研范围、用户需求、产品五层、AI 专项、三大数据系统、证据审计和可执行路线图。

## Schema 1.2

- `research`：模式、状态、时间、查询、范围、总结、缺口和搜索调用数。
- `userNeeds`：人物、场景、痛点、Kano 和 HMW。
- `market.signals`：需求、供给、政策、速度四类信号。
- `competitors[].fiveLayers`：战略、范围、结构、框架、表现。
- `dataSystems`：用户、增长、营收指标系统与 5W2H 埋点。
- `opportunities[]`：价值、风险、负责人、资源、依赖、实验、成功标准和下一步。

## 错误处理

- 联网请求最多重试两次瞬时网络错误。
- 权限拦截、鉴权、模型不支持和超时返回不同错误码与中文提示。
- 联网搜索没有形成有效 URL 时标为 `partial`，不伪装为完整调研。
- 关闭联网调研时仍可使用用户粘贴的材料完成离线分析。

## 验证

- 单元测试覆盖 Responses 请求体、输出提取、Schema 1.2 归一化和证据上限。
- 现有演示数据必须完整渲染新页面。
- 浏览器验证单产品输入、调研状态、深度拆解、证据审计和路线图。
- PPTX/DOCX 冒烟测试继续通过，并在 Word 中保留新增分析章节。
