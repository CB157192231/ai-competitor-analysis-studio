# AI 竞品分析方法

## 1. 用户需求

先写清用户、场景、问题和期望结果，再判断需求层级：

- 必备：缺失会显著不满，但具备不一定提升满意度。
- 期望：表现越好满意度越高。
- 魅力：超出预期并形成传播。
- 无差异/反向：减少或避免无效投入。

用 HMW 把问题转成机会，但不要在证据不足时直接跳到方案。

## 2. 行业与阶段

用需求、供给/规模、政策、发展速度四类信号判断趋势。再记录：当前行业规模信号、关键里程碑、下一转折。参考 Gartner 曲线区分萌芽、摸索、上升、爆发、泡沫和成熟，判断不同阶段应该验证、抢占或守住什么。

## 3. 产品五层与核心链路

- 战略层：愿景、定位、用户需求、商业模式。
- 范围层：主要/核心/次级能力。
- 结构层：信息架构、业务流程、用户路径。
- 框架层：页面、导航、控件与信息优先级。
- 表现层：视觉、文案、反馈、品牌与可用性。

比较必须回到核心链路：获知 → 激活 → 完成核心任务 → 留存 → 付费/传播。

## 4. AI 专项九维

| 维度 | 关键问题 | 默认权重 |
|---|---|---:|
| 市场匹配 | 是否解决高价值、高频或强痛点任务 | 12% |
| 产品体验 | 上手、链路、反馈、可控和结果交付 | 14% |
| AI 能力 | 模型策略、效果、模态、工具调用、上下文 | 18% |
| 信任安全 | 引用、幻觉、隐私、权限、审计、安全 | 10% |
| 增长 | 获客、激活、传播、渠道和留存机制 | 10% |
| 商业化 | 定价、付费价值、LTV/CAC 和毛利 | 12% |
| 成本效率 | 推理、服务、人力和边际成本 | 10% |
| 生态 | API、连接器、伙伴和开发者供给 | 7% |
| 创新 | 新交互、新数据闭环和难复制能力 | 7% |

每个评分格必须同时记录三项：一句可复核的评分理由、一个或多个有效证据 ID、置信度。证据只支持相邻事实时，不得跨维度复用来制造“全维度有证据”的假象。没有有效证据 ID 的维度最高 5 分；来源冲突时按较低置信度评分并保留冲突说明。

## 5. 数据系统

分别梳理用户、增长和营收系统。北极星指标应连接核心用户价值与业务向好，易于理解、可操作、最好是先导指标，并配套质量、成本和风险护栏。埋点需求用 5W2H 说明为什么采、采什么、在何处/何时/由谁采以及如何使用。

## 6. 商业效率

先识别广告、会员、知识/服务付费、金融、电商、分销、打赏、授权等变现模式，再用三级火箭拆解：提高访问、提高 ARPU、提高回访。把每一级写成指标树，并为最弱环节安排最小实验。

## 7. 决策汇报

结论先行，采用背景、过程、期望、计划四元素。汇报聚焦目标、方法、资源，带方案而非只报问题。每项建议说明价值、证据、风险、投入、负责人/依赖、成功指标和下一步。

建议的信心分必须绑定证据 ID。无证据的建议可以进入待验证池，但信心不得高于 5；优先把它改写成能获取新证据的最小实验。

## 8. 黄金任务实测

九维评分和界面审计回答“看起来能做什么”，不能代替同一份工作对照实验。

建立 5–8 个黄金任务：事先写清任务、材料和交差标准，三个产品用同一份。每个格子只记录实测：

- 是否交差
- 人工介入次数
- 首次可用结果（分钟）
- 产物能否直接用
- 失败后能否继续
- 本次费用

没有跑过的格子写「未跑」。禁止根据官网、功能清单、界面截图或宣传材料把格子改成通过。未跑不等于失败，也不等于能力缺失；它只说明这次分析还没有实测。
